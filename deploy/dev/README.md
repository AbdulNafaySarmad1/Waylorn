# Local integration services

This Compose file is for localhost verification only. It runs PostgreSQL, Keycloak, Valkey, NATS JetStream, and Redpanda without production security settings. Ports bind to loopback.

Create `deploy/dev/.env` with random `WAYLORN_DB_PASSWORD` and `WAYLORN_KC_ADMIN_PASSWORD`, then run `docker compose --env-file deploy/dev/.env -f deploy/dev/compose.yaml up -d`. The `.env` file is ignored by Git. Stop with `docker compose --env-file deploy/dev/.env -f deploy/dev/compose.yaml down`; do not use `down -v` unless test data can be discarded.

Use this stack only to verify migrations, live identity, cache loss, and broker contracts. It is not a supported deployment profile.

Run `pwsh -File deploy/dev/bootstrap-keycloak.ps1` after Keycloak is ready. The script creates a local `waylorn` realm, an API client, a confidential web client, a site-scoped workload client, and separate administrator and approver users. It stores random test passwords, client secrets, and scope IDs in the ignored `.env` file; no passwords are printed. The script writes an ignored `apps/web/.env.development.local` with the local API and Keycloak settings. Direct grant is enabled only for the local smoke client.

Start the .NET API on `http://127.0.0.1:18081` with `ASPNETCORE_ENVIRONMENT=Development`, `Authentication__Authority=http://127.0.0.1:18080/realms/waylorn`, `Authentication__Audience=waylorn-api`, `Authentication__AllowInsecureLoopback=true`, `ConnectionStrings__Waylorn` for the local database, `Audit__KeyId` and `Audit__SigningKey` from the ignored `.env`, `Eventing__Enabled=true`, `Eventing__NatsUrl=nats://127.0.0.1:14222`, `Eventing__KafkaBootstrapServers=127.0.0.1:19092`, `Eventing__BootstrapDestinations=true`, and `Cache__Endpoint=127.0.0.1:16379`. Read the database password and signing key from the ignored `.env`; never paste them into a committed configuration file. `/health/ready` verifies PostgreSQL and Keycloak discovery; `/health/eventing` verifies both NATS streams and the Redpanda audit topic without removing API readiness during broker outages. Run `pwsh -File deploy/dev/smoke.ps1` to register the local organization/site and verify real JWT validation, PostgreSQL-backed asset creation, an AMBER approval record for a compute asset, audited RED request denials, signed audit readback, incident and maintenance transitions, and bounded topology/impact views. Query `Outbox` to confirm `PublishedUtc` is set after broker acknowledgement. Production eventing must provision both `WAYLORN_CONTROL` and `WAYLORN_OPERATIONS` JetStream streams, plus the audit Redpanda topic.

For the read-only OT simulator, also set `Telemetry__AcceptRawObservations=true` on this site-local API. The Go gateway accepts raw observation destinations only at numeric loopback IP addresses. Build `ot-observe` with `cargo build --manifest-path crates/ot-core/Cargo.toml --target x86_64-pc-windows-gnu --release --offline --bin ot-observe`, then build the Go gateway from `src/network-plane/waylorn-gateway` with `go build -o bin/waylorn-gateway.exe .`. Run `pwsh -File deploy/dev/smoke-ot.ps1` while the API is running. It starts a one-shot loopback Modbus simulator, invokes Rust through Go, and checks the value and gateway heartbeat through the authenticated API. The ignored `deploy/dev/spool` holds any unacknowledged observations. This test does not contact physical equipment.

For a browser check, start the web app with `npm exec --yes --package=pnpm@10.33.0 -- pnpm --filter @waylorn/web dev`. Set `WAYLORN_TEST_ADMIN_PASSWORD` from the ignored `deploy/dev/.env` in your shell and run `node apps/web/scripts/local-integration.mjs` after both smoke scripts. The script signs in through Keycloak and verifies PostgreSQL-backed Assets, Sites, Live state, Telemetry, Incidents, and Maintenance pages. Playwright Chromium must be installed; `WAYLORN_BROWSER_EXECUTABLE` can point to an existing Chromium executable. The local web client and loopback HTTP issuer are development settings only.
